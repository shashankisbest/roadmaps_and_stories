# Roadmaps & Stories backend

## Setup

1. Create and activate a Python virtual environment.
2. Install dependencies: `pip install -r requirements.txt`.
3. Copy `.env.example` to `.env` and fill in local PostgreSQL settings. Do not commit `.env`.
4. Ensure PostgreSQL is running and the configured database exists.
5. Run the commands below from this directory.

This project reuses Django's existing `auth.User` table for accounts and stores
application-specific information in a one-to-one profile. This keeps the current
database migration history intact; passwords continue to use Django's password hasher.

```powershell
python manage.py makemigrations users posts comments notifications reports
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

For local development, set `DJANGO_DEBUG=true` in the local `.env` file. A
development-only fallback secret is used only while `DEBUG` is enabled. Before
deployment, explicitly set `DJANGO_DEBUG=false`, `DJANGO_SECRET_KEY`,
`DJANGO_ALLOWED_HOSTS`, and `DB_NAME`, `DB_USER`, `DB_PASSWORD`, and `DB_HOST`
through the deployment environment. Production startup fails if these required
values are absent or if the allowed-host list contains `*`. Configure explicit
frontend origins with `CORS_ALLOWED_ORIGINS`; production does not inherit local
LAN CORS/CSRF origins. HTTPS redirect, secure cookies, and one-year HSTS are
enabled by default with `DEBUG=false`; set `DJANGO_SECURE_SSL_REDIRECT` and
`DJANGO_SECURE_HSTS_SECONDS` to deployment-appropriate values when configuring
TLS termination. The default local-memory cache makes authentication throttles
process-local; use a shared Django cache for multi-worker deployments.

Run backend tests safely using Django's test database:

```powershell
python manage.py test
```

From the project root, `python run_tests.py` runs backend and frontend tests,
quality checks, the production-settings check, and saves output under
`test-reports/`.

New demo users have unusable passwords. The seed command uses placeholder
`@example.com` addresses and does not create authentication credentials; if an
account with a demo username already exists, its password and email are not changed.

## API

- `GET /api/health/` verifies database connectivity and returns only a status,
  not the database name.
- `GET /api/roadmaps/` and `GET /api/stories/` return paginated public resources;
  `GET /api/roadmaps/<id>/` and `GET /api/stories/<id>/` retrieve a resource.
- `GET /api/stories/?roadmap=<id>` filters to related stories;
  `GET /api/stories/?roadmap=independent` returns unlinked stories.
- `GET /api/auth/csrf/` supplies the CSRF token for browser requests.
- `POST /api/auth/register/` creates an account and starts a session.
- `POST /api/auth/login/` accepts `identifier` (username or email) and `password`.
- `GET /api/auth/current-user/` returns the signed-in user, or `{"user": null}`.
- `POST /api/auth/logout/` ends the current session.
- `GET /api/posts/<id>/comments/` returns a nested comment tree.
- `GET /api/profiles/<username>/` returns public profile details and posts.
- Authenticated write endpoints: `POST /api/posts/create/`,
  `PUT|DELETE /api/posts/<id>/`, `POST|DELETE /api/posts/<id>/like/`,
  `POST /api/posts/<id>/comments/`, `DELETE /api/comments/<id>/`,
  `POST|DELETE /api/profiles/<username>/follow/`,
  `GET /api/notifications/`, and `POST /api/reports/`.

Public feed endpoints use page-number pagination (`?page=2`). Mutations require Django
session authentication. Browser clients must send credentials and the `X-CSRFToken`
header for state-changing requests. The session cookie is HttpOnly; do not expose it to
JavaScript or store authentication tokens in browser storage.

Roadmap graph previews are generated by the browser from the saved graph and uploaded
with post creation as a size-limited PNG. Django stores them using its configured
default file storage under `roadmap_previews/`; local development uses `MEDIA_ROOT`
(default `backend/media`, configurable with `DJANGO_MEDIA_ROOT`) and serves `MEDIA_URL`
(default `/media/`) while `DEBUG=true`. Keep this directory persistent if Django restarts.
In production, configure a durable shared media volume or set Django's
`STORAGES["default"]` to the project's supported object-storage backend, and serve the
configured `MEDIA_URL` from that storage. The media URL returned by the API must be
reachable by the frontend. Existing roadmaps without preview files continue to return
`preview_url: null`.

For a frontend hosted on a different site from the API, set
`SESSION_COOKIE_SAMESITE=None` and `SESSION_COOKIE_SECURE=true` over HTTPS. Add the
frontend origin to both `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS` (the latter is
derived from the former). Local development defaults to `SameSite=Lax`.
